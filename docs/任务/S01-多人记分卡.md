请先读取：

- 根目录 `AGENTS.md`
- `docs/产品说明.md`
- `docs/技术架构.md`
- 当前 `src/App.tsx`

- 当前净山湖 course / hole / par 数据结构
- 当前 localStorage / Field Test 持久化实现
- 当前 GitHub Pages 部署配置

本轮名称：

Thread S01｜多人高尔夫记分卡

这是一个与 Field Test / GPS 数据采集相对独立的产品功能。

目标：

在现有 Golf Green Vision 中增加一个真正适合手机使用的：

“多人高尔夫记分卡”

最多支持同组 4 人。

不要修改或破坏现有 Field Test Mode。

- 浏览器自动化
- build

- Git
- GitHub push
- GitHub Pages deployment

请尽量在任务开始阶段集中申请。

不要做到一半再零散申请权限。

不要要求用户开启完全访问 / 无限制模式。

Git、commit、push、Pages 更新全部由你完成，
不要要求用户手动执行 Git。

==================================================
二、产品入口
==================================================

在当前应用增加清晰入口。

至少区分：

- 现场测试
- 记分卡

不要把两套功能全部堆在同一个长页面。

可以使用：

顶部 Tab
或
首页功能入口

以当前项目结构最简单、移动端最自然的方式实现。

记分卡页面名称：

高尔夫记分卡

==================================================
三、玩家
==================================================

支持：

1～4 名玩家。

每名玩家至少包含：

- playerId
- name
- avatar
- tee
- scores

页面左侧 / 玩家信息区域需要明确显示：

头像 + 人名

不要做账号系统。

本轮头像采用简单本地方案即可，例如：

- 内置头像 / Emoji
- 或根据名字生成圆形首字头像

不需要实现：
- 账号头像
- 云端头像
- 复杂图片上传

玩家必须可以：

- 添加
- 删除
- 修改姓名
- 更换头像
- 修改 Tee

最多4人。

至少1人才能正式开始记分。

==================================================
四、Tee / 梯台选择
==================================================

每个玩家独立选择 Tee。

不要把 Tee 设置成整组统一。

当前净山湖已有：

- Gold
- Blue
- White
- Red

如果项目现有数据中还有其他合法 Tee，
可以按实际数据支持。

不要硬编码不存在的 Tee。

Tee 的主要作用：

- 显示玩家所选梯台
- 显示对应 Hole 距离（如果数据存在）

注意：

玩家选择不同 Tee，
不影响“实际杆数”的输入逻辑。

Par 继续来自 Hole 数据。

==================================================
五、实际杆数
==================================================

每洞记录：

实际打出的总杆数。

例如：

Hole 1
Par 4
玩家实际用了5杆

应保存：

5

不是：
+1

不是：
Par + 1 的其他派生表示。

所有统计都从实际杆数计算。

未填写 Hole：

显示 `—`

不要默认成0。

==================================================
六、记分交互
==================================================

手机端优先。

每洞记分需要非常快速。

建议每名玩家在当前 Hole 显示：

头像  张三
蓝Tee

[-]   5   [+]

允许：

- `+`
- `-`
- 点击数字直接输入

最低合理值不要允许出现0或负数。

如需设上限：

使用合理的宽松上限，
不要阻止异常高杆数。

尽量保证：

一只手也容易操作。

==================================================
七、前九 / 后九
==================================================

明确分成：

前九：
Hole 1–9

后九：
Hole 10–18

允许用户快速切换：

前九 | 后九

至少显示：

前九小计：
OUT

后九小计：
IN

全部完成后：

TOTAL

不要要求一次性把18洞横向塞满手机屏幕。

移动端优先使用：

- 当前 Hole 卡片
- 前九 / 后九导航
- 或合理横向滚动

以实际易用性优先。

==================================================
八、Par 与 Hole 信息
==================================================

每洞显示：

- Hole number
- Par
- 当前玩家 Tee 对应距离（如果有）

例如：

Hole 6
Par 4
Blue 397 yd

如果距离数据不存在：

不要伪造。

只显示已有可靠数据。

当前记分计算：

相对标准杆 =
已完成 Hole 的实际总杆
-
这些已完成 Hole 的 Par 总和

==================================================
九、总杆与相对标准杆
==================================================

必须同时显示两种总成绩。

例如球场 Par 72：

实际总杆：
82

相对标准杆：
+10

最终 UI 可以显示：

82 (+10)

或者：

总杆 82
相对 Par +10

如果是低于 Par：

例如 68：

显示：

68 (-4)

如果正好：

72 (E)

其中：

E = Even

前九与后九也可以分别显示：

39 (+3)
43 (+7)

但总成绩至少必须同时有：

实际总杆
+
相对 Par

==================================================
十、未完成一轮时的统计
==================================================

用户不一定一次填满18洞。

因此统计必须区分：

“当前已完成 Hole 的成绩”

不要把未填写 Hole 当成0。

例如只打完前3洞：

5
4
3

对应 Par：

4
4
3

则当前：

12 (+1)

而不是拿它直接跟整场 Par 72 比。

页面需要避免误导用户。

==================================================
十一、多人记分显示
==================================================

最多4人同时记。

在当前 Hole 页面中：

左侧/上方：

头像 + 人名 + Tee

右侧：

实际杆数

例如：

Hole 7 | Par 4

🙂 张三  蓝Tee        [-] 5 [+]
🧢 李四  白Tee        [-] 4 [+]
😎 王五  蓝Tee        [-] 6 [+]
⛳ 赵六  红Tee        [-] 5 [+]

不要让用户必须逐个进入玩家详情才能记一洞。

一屏应尽量同时完成同组玩家当前 Hole 的记分。

==================================================
十二、记分卡总览
==================================================

增加一个：

“记分卡总览”

可以查看：

Hole 1–18
Par
每个人实际杆数
OUT
IN
TOTAL
相对 Par

桌面可以使用表格。

手机可以：

- 横向滚动表格
- 或前九 / 后九分开

但必须清晰。

最终效果应接近真实高尔夫 scorecard，
不要做成普通 Excel 输入表。

==================================================
十三、本地持久化
==================================================

记分数据保存到浏览器本地。

可以复用项目已有 localStorage 工具，
但不要与 Field Test Session key 混在一起。

记分卡使用独立 storage namespace。

刷新页面后：

- 玩家
- 姓名
- 头像
- Tee
- Hole scores

全部恢复。

==================================================
十四、新建 / 清空记分卡
==================================================

支持：

“新建记分卡”

如果已有数据：

必须二次确认。

不要一个误触直接清掉整轮成绩。

可以支持：

“继续上次记分”

或刷新后直接恢复。

==================================================
十五、Field Test 独立性
==================================================

记分卡与现场测试必须逻辑隔离。

不要：

- 因为切 Hole 改变 Field Test actualHole
- 因为记分卡清空删除 GPS Session
- 因为 Field Test 结束删除记分卡

两套数据分别保存。

以后可以考虑联动，
但本轮不要做。

==================================================
十六、数据结构
==================================================

建立清晰、简单的数据模型。

例如：

ScorecardSession

- id
- createdAt
- courseId
- players
- scores

Player：

- id
- name
- avatar
- tee

Score：

- hole
- strokes

尽量保持核心计算为纯函数。

例如：

calculateOut()
calculateIn()
calculateTotal()
calculateRelativeToPar()

不要把统计逻辑散落在 UI 组件里。
