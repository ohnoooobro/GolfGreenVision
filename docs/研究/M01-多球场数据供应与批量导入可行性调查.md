# M01｜多球场数据供应与批量导入可行性调查

**核实截止：2026-10-10（Asia/Shanghai）**<br>
**状态：研究报告，含已核实事实、第三方资料、工程推断和待询价事项**

## 1. 执行摘要

本轮没有找到一份可以不经合同确认、直接覆盖中国球场并允许公开发布的“全球 18 洞结构化 GIS 数据库”。但找到了两类真实供应信号：

1. **Golf API** 官网公开描述 REST API、CSV 导出、逐洞坐标、Tee/Green/POI 坐标和商业使用；价格、中国球场命中、边界/障碍物字段和完整许可仍未核实。它是技术形态上的候选，不足以直接成为采购决定。
2. **Golf Intelligence（StrackaGolf 公司）**公开提供 JSON API，说明其有 Tee、Fairway、Bunker、Penalty Area、Hole Outline、Green 多边形，Scorecard 和 3D Green Slope；Starter 公开价格为 **399 美元/月、10,000 credits**。公开条款允许授权应用内的数字地图、距离和果岭坡度展示，但禁止 A-Z 批量下载、建立本地全量仓库、原始输出再分发和打印竞品码数本。它最值得进入正式询价和三球场命中测试，但不能按“可以买断数据”理解。

目前没有证据证明上述供应商覆盖净山湖，也没有证据证明任何竞品的中国底层地图可供第三方采购。Golfshot 的官方/应用商店说明证明其具备全球 GPS、障碍物、3D 洞预览和自动追踪；VOOGOLF 的公开 App Store 记录证明其曾宣传 30,000+ 球场、实时 GPS 和误差小于 3 码，但官网本轮证书错误，覆盖和数据授权不能由宣传语推定；GolfLive 当前官网公开内容集中在赛事、记分和同步，未见 GPS/GIS 服务声明。

对净山湖，**不应等待未经确认的外部数据再开始 05B**。现有 OSM 只有未编号 Green/Tee 几何，05A 只有 H17 为 `strong-candidate`，其余 13 洞 `conflicting`、4 洞 `insufficient`；外部数据即使命中，也仍要做坐标系、年份、洞号和授权校验。建议并行进行小规模供应商样本测试和独立人工审核，人工审核结果不得直接覆盖正式 `course.geojson`。

100 座以上的瓶颈不是 GeoJSON 写入，而是**中国球场覆盖、洞号语义、许可边界和质量审核**。首要基础设施应是带来源、授权、版本、证据等级和人工审核状态的导入管线；路线以“合法供应商优先、缺失球场自行数字化、疑难洞少量现场补证”的混合模式最稳妥。

## 2. 证据等级与方法

- **A：官方一手页面或项目内可复核文件**。能证明页面声明或本地数据事实，不等同于合同履约或实测精度。
- **B：公开第三方资料/应用商店/公开地图**。可作线索或交叉核对，不自动成为真值或授权。
- **C：本轮工程推断或成本假设**。用于规划，不能写成市场报价。
- **D：尚未核实**。不能用于正式地图、覆盖率、价格或供应商承诺。

本轮只读访问公开页面、App Store 检索接口和本地 OSM/项目文件；未登录、未填写询价表、未下载受保护数据、未抓取竞品接口，也未把任何 API 响应写入仓库。无法访问的页面保留 URL、原因和下一步最低成本核实方式。

## 4. 商业数据供应商

### 4.1 Golf API（golfapi.io）

官方首页 [Golf API](https://golfapi.io/)（标题 `Golf API - Complete course database`）自称 40,000+ 球场、160+ 国家、持续更新，提供 REST API 和四类 CSV（clubs、courses、tees、coordinates），字段包括球场和记分卡、Par/Stroke Index、Tee/距离、Slope/Course Rating、Green/Tee/POI 坐标和逐洞坐标。页面写明可在自己的产品和服务中商业使用，同时禁止转售、再分发或向第三方共享，并允许存储/缓存获取的数据。其价格区域显示通用的 Free/Pro/Enterprise 文案，未给出可核对的球场数据价格；联系表单用于索取更多信息。

**已确认能力：A（官方宣传）**；**未确认事项：D**：中国球场命中（包括净山湖）、实际 CSV/API 样例、坐标精度和 CRS、Green/ Fairway/ Bunker/Water 边界、DEM/坡度、API 速率/更新 SLA、商业网页显示与离线缓存边界、违约后数据保留。不能把其“40,000+”当作中国覆盖率，也不能把“商业使用”当作再分发许可。

最低成本核验是发出一封指定球场询价，要求对净山湖及两座中国球场只读提供字段样例、命中/未命中结果、合同许可摘要和报价；本轮未发送。

### 4.2 Golf Intelligence / StrackaGolf

官方页面称 Golf Intelligence 是 Elite Golf Technology, Inc. dba StrackaGolf，数据由 StrackaGolf 提供。公开产品与文档明确列出：

- 课程搜索、Scorecard、Tee/多套梯台、Par/码数/Handicap；
- JSON GPS 多边形：Tee Box、Fairway、Bunker、Penalty Area、Hole Outline、Green；
- 3D Green Slope/Elevation 图像（页面标注 900×1620）和 live lie elevation/geohash；
- `getCourseGroupDetail` 一次返回 scorecard + GPS + metadata；GPS-only 2 credits，scorecard-only 1 credit，detail 3 credits；
- Search 免费；Tester 49 美元/月/100 credits（个人自用）；Starter 399 美元/月/10,000 credits（有用户的应用）；Facility 500 美元/年/每个 activated course，最低 2,000 美元/年、年度上限 15,000 美元，适用于授权球场内部设施产品；更大级别需联系。

**授权限制是决策关键：** Terms of Use（生效 2026-08-20，更新 2026-10-02）将普通用法定义为授权应用中的实时数字地图、距离、scorecard、坡度/高程显示；禁止 A-Z 或大比例目录下载、建立全量本地仓库/竞争数据集、转售/再许可/公开原始输出、把 API 用于训练/RAG/向量库、制作竞争性纸质码数本。条款允许特定球场的设备缓存最长一年（按计划和用户约束），但付费停止后 token 和缓存服务数据会失效；Starter 及以上仍是数字应用内使用。条款还写明 US/UK 高程较强，全球 lie elevation 不是承诺。

来源： [首页](https://golfintelligence.com/)、[API 文档](https://golfintelligence.com/docs/)、[GPS 层](https://golfintelligence.com/golf-course-gps/)、[价格](https://golfintelligence.com/api-pricing/)、[Terms](https://golfintelligence.com/terms-of-use/)、[数据集说明](https://golfintelligence.com/okf/dataset.md)，A，核实 2026-10-10。

**判断：** 这是目前最值得联系的结构化数据供应商，但它更像“按用户请求服务的授权 API”，不是可以导出后公开再分发的 18 洞数据库。中国覆盖、指定球场样本和合同中的商业网页/离线策略仍必须书面核实。

### 4.3 StrackaLine

StrackaLine 官方页 [strackaline.com](https://www.strackaline.com/) 可访问到应用壳和元数据，页面自述是自 2007 年提供 yardage books/greens guides 的全球球场搜索服务；本轮没有可公开读取的开发者 API、GeoJSON/SHP 下载、商业软件授权或中国球场清单。Golf Intelligence 条款明确 StrackaLine/StrackaGolf 是其数据权利方/许可方之一，但不能据此推断 StrackaLine 单独出售 API。

因此 StrackaLine 适合作为“专业测绘/绿图数据来源”联系对象，不适合作为已经确认的可编程 GIS 供应商。若联系，应询问数字产品授权、逐洞坐标/多边形是否可交付、是否允许第三方 App 显示和缓存；本轮未购买或下载书籍/绿图。

### 4.4 Golf Intelligence 之外的候选与中国服务商

本轮没有找到具有可复核官网、公开字段和价格的中国“高尔夫完整 GIS 数据库”。中国航测、无人机正射、测绘和矢量化公司通常可以按项目提供影像或定制测绘，但“能测绘”不等于“已有真实 Hole 1–18、Tee/Green 语义数据库”，也不等于取得公开软件再分发许可。对高德、百度、腾讯地图，本轮没有发现可直接取得完整 18 洞矢量内部数据的公开产品证据；POI/底图许可应单独核实。

可执行的中文询价模板：

> 我们开发高尔夫球场 GPS 辅助软件，拟核验净山湖及另外两座中国球场。请确认能否提供 Hole 1–18、每洞 Tee/Green（点或面）、Fairway、Bunker、Water/Penalty Area、洞方向/拓扑，格式（GeoJSON/SHP/KML/API），坐标系和采集年份；请分别报价单场、10 场和年度更新，并说明商业 App 显示、服务器缓存、派生数据、公开网页和再分发权限。请先提供一份不含受保护全量数据的字段样例或匿名化示例。

## 5. 公开数据与 OSM

OpenStreetMap 数据抽取后的许可为 ODbL 1.0；OSM Foundation 官方许可页说明来源应归属 OpenStreetMap，数据库使用和派生数据库需遵守 ODbL 的署名/相同许可与共享要求，具体公开服务是否触发“公开数据库”义务应让法务按产品形态判断。来源：[OSM Foundation Licence](https://osmfoundation.org/wiki/Licence)，A，核实 2026-10-10。标签参考页：[Key:golf](https://wiki.openstreetmap.org/wiki/Key:golf)，本轮页面读取受限；不把标签页未读取写成事实。

净山湖本地 Overpass 响应（2026-09-26，项目文件 `data/raw/osm-jingshanhu-golf.json`）有 26 个 `golf=green` 面、2 个 `golf=tee` 面，没有 `hole`、`ref` 或编号关系，并带 ODbL 声明。它能支持“球场周边有未编号地物”的初步底图，不能支持真实洞号、Tee/Green 归属或完整拓扑。其他中国球场的 OSM 完整度没有做出覆盖率统计，不能推广净山湖结果。

公开记分卡、球场宣传图和旅游预订页面可以补充 Par/距离/洞号顺序，但通常没有可配准的 Tee/Green 多边形，也不自动授予商业再利用权。Tiger Booking 的净山湖页面提供第三方 1–18 洞、Par 和距离表，但没有完整洞级 GIS：[Tiger Booking](https://www.tigerbooking.com/zh/cn/golf-course/Jingshanhu-Golf-Club-TACN0279)，B，项目核实 2026-09-26。

## 7. 影像与结构化数据的根本区别

净山湖 GeoTIFF 为 5852×6063、四波段、约 0.257571 m/像素、EPSG:4548。它回答的是“某像素在某投影坐标附近的颜色/反射”，不能单独回答：这个地物是第几洞、哪个 Tee 类别、哪一个 Green、障碍物属于哪洞、球洞顺序如何、坡度是多少。05A 的 2023 影像与 2026 现场 GPS 还存在年份和绝对控制点差异。

结构化数据至少应同时有 `course_id`、`hole_number`、`par`、`tee_set`、Tee 几何、Green 几何/中心、障碍物几何、CRS/坐标历元、来源、采集/更新日期、许可和审核状态。真实果岭坡度必须来自高程/坡度资料或合法供应商的 slope layer；不能从普通正射影像伪造。

## 8. 技术路线与批量导入

### 8.1 推荐的标准导入流程

1. **Source manifest**：记录来源 URL/合同 ID、供应商、采集年份、CRS、许可、缓存与再分发边界、抓取时间和内容哈希。
2. **原始隔离**：原始 API 响应、GeoTIFF、私人 GPS 放在 Git 忽略的受限目录；公开仓库只提交脱敏 manifest、字段字典和汇总证据。
3. **格式和坐标校验**：验证 GeoJSON/SHP/CSV schema、CRS、经纬顺序、单位、几何有效性和球场范围。
4. **语义规范化**：把供应商字段映射到内部 `course/hole/tee/green/hazard/topology`，保留原始 ID，不覆盖原值。
5. **自动质检**：洞号唯一性、Par/距离合理性、Tee→Green 方向、洞长排序、跨洞相交、Green/Tee 落在球场范围、空几何、重复几何和版本差异。
6. **候选与人工审核分离**：自动推断只生成候选；审核者必须看到来源、几何和证据，状态用 `unverified / candidate / reviewed / field-confirmed / rejected`。
7. **最小现场补证**：只对缺失洞号、Tee 距离异常、坐标系疑似错位或供应商冲突的洞安排定向采集；记录稳定时间戳、GPS accuracy、照片/标牌和审核人。
8. **发布门槛**：没有满足级别门槛的洞不得作为已确认地图发布；版本化保存变更原因和回滚点。

可以不做完整 18 洞现场采集来完成“初步空间映射”，前提是供应商/官方资料提供可信 Hole 编号和多边形，且坐标系、年份、许可均通过校验。人工审核仍不可省略；以下情况必须现场或球场权威资料确认：同一洞多簇、Tee/Green 与洞号冲突、地图年份变化、无法解释的 100 m 级偏移、真实坡度、以及发布前的关键洞。

### 8.2 Level 1–4 成熟度标准

| 级别 | 最低字段 | 发布能力 | 必须阻止发布的情况 |
|---|---|---|---|
| Level 1 基础记分 | 课程名/位置、18 洞编号、Par、Tee set 距离、来源和日期 | 记分卡 | 洞号或 Par 来源不明 |
| Level 2 球道地图 | Level 1 + 合法可显示的球场/洞/地物几何、CRS、许可、几何质检 | 逐洞图形，未确认关系必须显式标注 | 几何与洞号关系未审、许可不明 |
| Level 3 GPS 球场助手 | Level 2 + reviewed/field-confirmed Hole、Tee、Green 中心/边界、版本和误差说明 | 距离估算、辅助识洞和人工修正 | 仅最近邻推断、无独立洞号证据、坐标偏移未解释 |
| Level 4 真实果岭坡度 | Level 3 + 合法 DEM/DTM/坡度/坡向或供应商 slope layer、采集日期和精度 | 果岭坡度/高程显示 | 从正射影像或猜测生成坡度 |

等级合理，但应增加“每洞证据状态”而不是只给球场一个总等级；18 洞中任何一个洞仍可为 Level 1/2，不能因平均值升级整座球场。建议至少字段：`evidence_level`、`source_type`、`license_status`、`geometry_status`、`hole_identity_status`、`reviewer`、`reviewed_at`、`coordinate_epoch`、`accuracy_note`、`supersedes`。

## 9. 成本与规模化模型

以下为 **C 级工程估算，不是市场报价**。只有 Golf Intelligence 的公开订阅价格属于 A 级供应商报价；汇率暂不换算，人工按 150 元/小时、现场人工/交通按 2,000 元/球场日作为内部预算假设。实际采购前必须用书面报价替换。

### 9.1 单球场工作量假设

- 供应商 API：首次字段/许可核验 2–4 小时；导入和自动 QC 1–2 小时；人工审阅 1–3 小时；异常现场补证 0–1 天。
- 自行数字化：影像/控制点 0.5–1 天；半自动提取和矢量整理 4–12 小时；18 洞人工语义审核 4–12 小时；疑难球场现场 0–1 天。
- 混合模式：命中球场按 API 流程；未命中球场按自建流程；疑难洞才现场。

### 9.2 规模情景（不把假设写成报价）

| 路线/规模 | 10 座 | 100 座 | 1000 座 | 主要瓶颈 |
|---|---:|---:|---:|---|
| A 采购 API | Golf Intelligence Starter 约 4,788 美元/年（399×12，credits 是否足够取决于用户访问）；另加一次性导入/QC 约 3–10 人日 | API 账单约 4,788 美元/年起，但公开条款不允许 A-Z 预加载，100 座需按用户实时调用和许可设计；企业/量价需询价 | 不能按“下载 1000 座本地库”预算；必须谈 partner/enterprise、地区包或白标合同 | 中国命中、按用户 credits、缓存/离线限制、授权 |
| B 自行数字化 | 影像/测绘、人工和现场按每场 1–3 万元内部低/中/高情景，即约 10–30 万元；无公开报价 | 100–300 万元情景 | 1000–3000 万元情景，且需专职 QC/版本团队 | 人工洞号语义、影像许可、现场补证和更新 |
| C 混合 | 先对 3–5 场付费验证；命中场走 API，缺失场按每场 1–3 万元数字化；预计最能控制早期现金风险 | 供应商命中率和异常比例决定成本；预算按 30–60% API、40–70% 自建场景做敏感性分析 | 建立地区/供应商路由、审核队列和长期更新合同，避免每场都现场 | 供应商覆盖不确定和质量门槛 |

基础设施（对象存储、数据库、CI、日志）在 10–100 座通常低于人工和许可成本；1000 座时版本存储、队列、审核后台和监控会明显增加，但仍通常不是第一瓶颈。Golf Intelligence 的 10,000 credits 不能简单等于 10,000 座：完整球场 detail 每座 3 credits，且条款禁止系统性目录下载；对于有用户的应用，Tester 也不适用，至少要 Starter 或书面更高层级。

## 10. 授权、隐私和仓库安全

- 不提交净山湖购买 GeoTIFF 原件、私人 GPS/原始 JSON、竞品地图截图或未授权 API 响应。
- OSM 可用时要按 ODbL 做署名并评估派生数据库/公开服务义务；不能把 OSM 几何与商业数据混成无来源的单一资产。
- 购买文件不等于取得公开网页、离线缓存、派生数据和再分发权。每个供应商必须单独保存合同和许可版本。
- API token、联系表单数据和个人 GPS 不应写入报告；公开报告只保留 URL、页面标题、日期、字段级摘要和授权边界。

## 11. 净山湖 05B 决策

05B 不应等待外部数据。推荐顺序：

1. 先用现有私有 05A 派生表对 H17 做整洞人工审核，并排查 H4/H5/H6/H7/H8/H9/H10/H18 的 Green 线索；H3/H13 同洞 Green 冲突、H10 引用一致性问题单独列为阻塞。
2. 规划一次“定向补证”而非完整重打一轮：优先 H1/H11/H12/H14、H13 Tee、H15/H16 Green，以及 Tee 与候选地物相距较远的洞。到 Tee/Green 时明确选择类别并保留 `confirmed`，不得把 `inherited` 回填为实测。
3. 同时向 Golf Intelligence 和 Golf API 索取净山湖命中/字段/许可样例；若外部样例命中，先在隔离目录比较 CRS、洞号、几何和年份，不能直接覆盖正式 `course.geojson`。

## 12. 五个决策问题

**问题 1：是否有足够证据把“购买结构化球场数据”作为主要扩展路线？**<br>
暂不能把它作为唯一主路线；有足够证据把“供应商 API 小规模验证”列为主要试验路线。Golf Intelligence 的字段、价格和条款是真实信号，但中国覆盖和可发布边界未验证；Golf API 的中国命中和价格更不明确。

**问题 2：中国球场哪条路线最可行？**<br>
当前最可行的是混合模式：合法 API/已有数据优先，公开 OSM/记分资料只作辅助，自行数字化覆盖缺口，疑难洞少量现场核实。纯公开数据无法解决净山湖洞号；纯现场采集难以规模化；纯商业 API 尚无中国覆盖证据。

**问题 3：净山湖 05B 等外部数据还是先人工审核？**<br>
先人工审核并行询价，不等待。05A 已有足够线索形成定向补证清单，而供应商命中尚未确认。外部数据只能作为独立证据，不能替代现场洞号审核。

**问题 4：100 座以上最值得先开发什么基础设施？**<br>
开发版本化导入管线和审核队列：来源/许可 manifest、CRS 和几何 QC、供应商字段适配器、候选与确认分离、逐洞证据等级、人工审核日志和可回滚版本。它直接降低错误地图发布风险，比先做更复杂的自动识洞算法更关键。

**问题 5：下一步立即做哪 3 项小验证？**

1. 给 Golf Intelligence 和 Golf API 各发一份指定四球场询价，要求净山湖、深圳观澜湖、海口观澜湖和一座国际球场的命中、字段样例、CRS、更新和商业授权；不要求全量导出。
2. 在隔离目录实现一条只读导入器，用脱敏/最小样例验证 `scorecard + Tee/Green/hazard polygon + hole_number` 到内部 schema 的映射、CRS、洞号唯一性和授权 manifest。
3. 按 05A 清单完成净山湖一次定向现场补证，重点补缺失洞和冲突洞；输出人工审核表，不改正式地图，比较“供应商命中 + 人工审核”与“纯自建”每洞耗时和错误类型。
