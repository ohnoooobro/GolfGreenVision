# 0004｜净山湖 V0 数据方案

日期：2026-09-26

## 决策

1. 建立 `data/derived/jingshanhu/course.geojson` 作为交换格式，运行时通过 `src/course/jingshanhuCourse.ts` 提供静态类型数据。
2. GeoJSON 只放运行时需要的洞号、Par、四档码数、几何和字段状态；来源 URL 和验证说明通过 `provenance` 引用，详细调查放在 `data/metadata/`。
3. 采用 Tiger Booking 逐洞表记录 1-18 洞 Par 与四档码数，但标记为 `unverified`。Bestdo 的 7,312 码和 Tiger 页面中的 7,158/6,631/6,098/5,419 码存在冲突，冲突写入来源记录，不自行选择“官方值”。
4. 公开资料不足以可靠配准逐洞 Polygon 和果岭中心，因此两类几何均使用 `null`，不填充猜测坐标。`inferHole` 跳过 geometry 缺失的洞。
5. GeoJSON/运行时类型采用字段级状态：`holeNumberVerified`、`parStatus`、`polygonStatus`、`greenCenterStatus`，保留旧 `verified` 字段以兼容 Mock 数据。
6. correctedHole 在传入当前球场洞号列表时校验存在性；无效洞号被清除，避免写入不存在的洞。

## 原因

本轮目标是第一次真实现场测试的数据底稿。可追溯的部分数据比“填满 18 洞”的伪坐标更有价值；现场采样后再补几何可以直接验证边界和 GPS 漂移假设。

## 后续验证

现场测试需要先采集实际洞序、发球台和果岭点，再建立宽松且不自交的 Polygon。V1 前必须完成 WGS84/来源坐标确认、相邻洞重叠检查、外环/顶点/共享边界/内环测试。
