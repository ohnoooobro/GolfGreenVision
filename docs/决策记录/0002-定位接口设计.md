# 0002｜定位接口设计

## 决策

真实 GPS 和桌面模拟定位都实现同一个定位来源接口，由 `LocationController` 对外提供统一的 `LocationState`。页面、后续地图和洞号识别只消费统一的经纬度、精度和时间字段，不需要知道数据来自浏览器还是模拟器。

## 原因

- 现场测试需要浏览器真实定位，桌面开发需要可重复、可手动改变的位置。
- 共用接口可以让模拟数据验证页面和后续计算逻辑，而不会把浏览器 API 细节扩散到业务层。
- 控制器集中管理来源切换和生命周期，避免同一时间创建多个 `watchPosition` watcher。

## 当前定位数据结构

`LocationData` 包含：`latitude`、`longitude`、`accuracy`、`altitude`、`heading`、`speed`、`timestamp`。后三个可用 `null` 表示浏览器没有提供值。坐标按 WGS84 语义使用；本轮不做坐标系转换。

`accuracy` 原样展示为浏览器提供的水平精度估计值，单位为米。它不被解释为球的位置精度。

## 浏览器定位限制

浏览器定位依赖 HTTPS（本机开发的 localhost 通常例外）、设备定位服务和用户授权。权限拒绝、定位不可用、超时与其他错误会转换为明确的中文状态。页面隐藏、系统省电策略和设备环境也可能让更新变慢或精度变差。

## 本轮暂不记录轨迹

本轮只建立当前位置基础设施。轨迹记录涉及采样策略、前后台行为、本地存储容量、隐私和导出格式，需要先完成定位稳定性验证后单独设计；因此本轮不持久化任何定位轨迹。
