# 0005｜净山湖 V0.5 地理配准方案

日期：2026-09-26

## 背景

V0 已有净山湖 18 洞洞号、Par 和四档 Tee 距离，但没有可复核的洞级空间坐标。本轮目标是为后续 GPS 洞号识别和到果岭距离计算准备最小可用的 Tee、Green 和 centerline 数据。

## 调查结果

1. Tiger Booking 页面提供 1-18 洞表和 4 张公开图片。图片已保存到 `data/raw/tiger-01.jpg` 至 `data/raw/tiger-04.jpg`，检查后确认为景观/设施照片，不是逐洞图。
2. OpenStreetMap Overpass 在球场范围内提供带 WGS84 坐标的 26 个未编号 `golf=green` 面和 2 个未编号 `golf=tee` 面，并有球场范围、道路、沙坑和水面要素。
3. OSM 要素没有 `hole`、`ref` 或编号关系，公开资料也没有找到可以把这些要素对应到 Tiger 1-18 洞的逐洞示意图。

## 决策

- 本轮不把任何未编号 OSM Green/Tee 赋给洞号。
- 18 洞的 `teeCenter`、`greenCenter`、`centerline` 全部保留 `null`，`spatialConfidence=none`，`spatialVerified=false`。
- 18 洞的 `spatialDigitization=none`、`spatialEstimated=false`；三个空间字段均引用 V0.5 元数据，明确记录为何没有可用坐标。
- 运行时和派生 GeoJSON 使用 WGS84 `[经度, 纬度]`；没有 GCJ-02/BD-09 转换。
- 继续保留原始 OSM JSON 和公开图片，来源与限制写入 `data/metadata/jingshanhu_sources.md` 和 `data/metadata/jingshanhu_v0_5.md`。
- 增加坐标合法性、端点方向、Tee/Green 重合、码数数量级和相邻洞异常校验，为后续人工数字化提供门槛。

## 放弃的方案

- 用 Tiger 图片像素位置推算经纬度：图片没有逐洞编号，也没有地图控制点，不能审计。
- 用球场级 Tiger/Bing 坐标平移生成 18 洞坐标：只能定位球场，不能区分洞号和 Tee/Green 方向。
- 按 OSM Green 的空间顺序猜测 1-18 洞：OSM 只有未编号要素，且有 26 个 Green，存在练习区或重复/补充要素，无法可靠排序。

## 后续进入条件

只有取得以下任一组合后，才进入洞级配准：

- 带明确洞号的公开球道图 + 可核对的 WGS84 影像/地图控制点；
- 球场授权的逐洞坐标或 KML/GeoJSON；
- 现场授权采样的 Tee、Green GPS 点，并记录 accuracy、采样时间和坐标系统。

在此之前，V0.5 不宣称可进行真实 GPS 洞号判断或距离计算。
