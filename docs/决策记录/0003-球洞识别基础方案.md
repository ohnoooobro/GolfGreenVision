# 0003｜球洞识别基础方案

## 决策

第一版使用 GeoJSON Polygon containment 判断当前位置属于哪个球洞区域。统一位置数据只提供 WGS84 经纬度，识别模块不关心位置来自浏览器 GPS 还是桌面模拟器。

当点位只命中一个 Polygon 时，直接返回该洞；没有命中时返回无法确定；命中多个相邻区域时，保留全部候选并按洞号升序，暂时选择最小洞号作为自动判断结果。这个规则是确定的、可测试的，也能让重叠区域在调试页面中被看见。

## 为什么暂时使用 Polygon containment

- 球洞区域是当前最小且直观的数据单元，GeoJSON 可以同时保存区域、洞号、来源和验证状态。
- 点在区域内的判断是纯函数，容易用模拟坐标覆盖单洞、重叠和区域外三类情况。
- 现阶段只有 Mock / Demo 数据，复杂模型无法获得足够可靠的真实输入。

## 洞号状态

- `inferredHole`：算法根据当前位置得到的洞号，无法判断时为空。
- `correctedHole`：用户手动选择的洞号，未修正时为空。
- `effectiveHole`：界面和后续业务实际使用的洞号；有 `correctedHole` 时使用它，否则使用 `inferredHole`。

定位更新只更新 `inferredHole`，不会覆盖已有的手动修正。清除手动修正后，`effectiveHole` 会重新跟随自动判断。

## 当前已经解决的问题

- 使用统一 `LocationData` 判断点是否在 Polygon 内。
- 支持单一命中、所有区域外和多个重叠候选。
- 保留候选洞号，便于后续改进规则。
- 在开发页面显示自动洞号、候选洞号、实际使用洞号，并支持手动修正。

## 当前还不能解决的问题

- Polygon 不能表达洞与洞之间的行进连续性，也不能处理 GPS 漂移造成的边界抖动。
- 多候选时按最小洞号只是临时规则，不能代表真实球场上的正确洞号。
- 当前数据是明确标注的 Mock / Demo，不代表任何真实球场；没有实现果岭距离、球道中心线或轨迹上下文。

## 接入真实球场数据前需要验证

1. 核对每个 Polygon 的坐标来源、WGS84 坐标系和洞号，确认是否存在自交、空洞和跨越经度边界等几何问题。
2. 分别验证球洞区域、果岭中心、来源和验证状态，不能把估算或未验证数据写成确定事实。
3. 用现场采样点检查边界、相邻洞重叠和 GPS accuracy 对识别结果的影响。
4. 决定多候选时是否引入上一洞连续性、球道中心线距离和果岭距离，并为每条规则增加可重复测试。
