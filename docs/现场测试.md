## 1. 出发前准备

在手机上打开现场测试页面，逐项确认：

- [ ] 浏览器支持 Geolocation API。
- [ ] 页面处于安全上下文（真实设备使用 HTTPS；本地调试地址符合当前浏览器要求）。
- [ ] 已允许本页面使用定位；若拒绝过权限，已在浏览器设置中恢复。
- [ ] 页面成功收到至少一次定位，显示最后更新时间和 `accuracy`。
- [ ] 页面能明确显示当前是**真实定位**还是**模拟模式**；真实下场必须是非模拟模式。
- [ ] 浏览器本地存储可写入、可读取。
- [ ] 候选数据已加载，并能看到候选数据版本。
- [ ] 页面提供 JSON 导出；可先用模拟数据下载一个小文件并删除该文件，确认浏览器允许下载。
- [ ] 手机电量、移动网络或离线部署方案满足整轮测试；屏幕在阳光下可读。
- [ ] 已准备纸笔或语音备注，用于记录标牌、球道方向、水体/沙坑等独立证据。

## 2. 开始 Session

- [ ] 点击“开始现场测试”。
- [ ] 页面创建唯一 `sessionId`，显示开始时间。
- [ ] Session 至少记录：`courseId=jingshanhu`、App/数据版本、候选数据版本，以及必要的非敏感设备/浏览器信息。
- [ ] Session 保留本轮定位来源（`real` 或 `simulated`）；模拟验收数据不得与真实 GPS 记录混淆。
- [ ] 首次进入时 `actualHole` 可以为空；在设置实际洞号前不要采样。
- [ ] 主界面显示定位状态和 `accuracy`；经纬度可放在“调试信息”折叠区域。
- [ ] 确认页面没有因系统预测自动改变 `actualHole`。

### 定位状态的记录规则

`accuracy` 是浏览器返回的水平精度估计值，不是球的位置精度，也不代表测绘精度。现场模式只用下列分段做可读性提示；低精度不会阻止采样，无定位则等待有效位置：

- `无定位`：没有有效位置，或定位回调尚未返回。
- `良好`：`accuracy <= 10 m`。
- `一般`：`10 m < accuracy <= 25 m`。
- `较差`：`accuracy > 25 m`。

如果显示“较差”，阅读提示后仍可继续采样，样本会保留当时真实的 `accuracy`。如果尚未收到有效定位，Tee/Green 会拒绝保存；先等待定位回调，避免导出缺少坐标的样本。

## 3. 每一洞的操作

对 Hole 1–18，按现场实际顺序重复以下步骤。**不要依赖系统自动换洞。**

### 3.1 明确实际洞号

- [ ] 到达该洞起点前，使用 Hole selector、上一洞或下一洞，把页面顶部的 `actualHole` 设置为现场确认的 Hole 号。
- [ ] 如果暂时无法确认，保持为空或按页面支持的方式记录为 `uncertain`；在确认前不保存 Tee/Green 样本。
- [ ] 查看“系统预测”及其 `candidate` / `high-confidence-inferred` 状态。候选排序分只是排序分，不是正确概率。
- [ ] 记录能帮助复核的独立证据：发球台标牌、球道方向、转场、明显水体/沙坑、果岭入口等。

### 3.2 到达发球台（Tee）

- [ ] 站在发球台区域，等待页面显示最新定位时间和 `accuracy`。
- [ ] 点击“到达发球台”。若 `actualHole` 为空，页面应拒绝保存并给出清晰中文提示。
- [ ] 若没有定位或 `accuracy` 较差，阅读提示后决定是否继续；不要把低精度样本伪装成高精度样本。
- [ ] 确认新增样本的 `sampleType=tee`、`source=field`，并关联当前 `actualHole`。
- [ ] 确认样本保留 `sessionId`、时间、WGS84 经纬度、`accuracy`，以及可用的 altitude/heading/speed、当时 `predictedHole` 和 candidate mapping 信息。
- [ ] 同一洞需要重采样时可以再次点击；每次点击都应生成独立样本，不覆盖之前的样本。

### 3.3 到达果岭（Green）

- [ ] 进入果岭区域，等待一次定位更新后点击“到达果岭”。
- [ ] 确认新增样本的 `sampleType=green`、`source=field`，并关联当前 `actualHole`。
- [ ] 记住该点的真实含义：这是“用户到达果岭区域时的位置”，不等于旗杆位置、果岭几何中心或官方 Green Center。
- [ ] 确认样本与 Tee 样本一样保留当时的 GPS、`accuracy`、`predictedHole` 和候选信息；允许同一洞多次采样。

### 3.4 预测确认

- [ ] 预测正确时点击“正确”，生成 `actualHole = predictedHole` 的确认事件。
- [ ] 预测错误时点击“实际是其他洞”，选择现场实际 Hole 1–18，生成独立确认事件。
- [ ] 无法判断时点击“暂不确定”，生成 `actualHole=uncertain` 的确认事件。
- [ ] 如果页面顶部已经设置了当前实际洞号，可使用“用当前实际 Hole 校验系统预测”快捷操作，避免再次选择洞号。
- [ ] 确认事件不得改写原始样本，也不得直接把候选数据标成已验证。

### 3.5 切换到下一洞

- [ ] 离开本洞前确认 Tee/Green 和确认事件是否已记录；未采完整时可在备注中说明。
- [ ] 通过上一洞/下一洞或 Hole selector 手动切换 `actualHole`。
- [ ] 切换洞号不会删除上一洞数据，也不会自动改变系统预测。

## 4. 误触、低精度和中断处理

- [ ] 误点采样后，只使用“撤销上一条采样”或本洞样本列表删除明确的一条；确认没有清空整轮数据。
- [ ] 删除错误样本后，确认其他洞样本、确认事件和轨迹仍存在。
- [ ] `actualHole` 为空时，确认 Tee/Green 保存按钮被拒绝；不要为了绕过提示填入猜测洞号。
- [ ] GPS 暂无定位时，先等待更新；在收到有效定位前，Tee/Green 保存应被拒绝并给出提示。
- [ ] GPS 精度较差时可以继续采样；在备注中写明现场环境或等待时间。
- [ ] 页面切到后台、锁屏或刷新后重新打开，选择“恢复未完成测试”；确认同一 `sessionId` 和已有数据仍在。
- [ ] 浏览器意外关闭后重新进入，优先恢复未完成 Session，再继续操作；不要新建 Session 覆盖旧数据。

## 5. 轨迹记录抽查

Session 运行期间页面可以记录轻量 GPS track。当前策略为：

- 第一个有效定位回调立即记录一个点；
- 后续仅在距上个 track point 至少 `10 秒`**或**移动至少 `10 m` 时记录，避免高频重复点；
- 每个点至少包括 `timestamp`、WGS84 `latitude`/`longitude`、`accuracy`、当时的 `actualHole` 和 `predictedHole`；
- 轨迹只属于当前 Session，定位无效时不伪造坐标；
- 轨迹记录不能阻塞 Tee、Green、确认事件或导出。

现场抽查：

- [ ] 走动一段距离后 track 点数量增加，但没有每次渲染都增加重复点。
- [ ] 切换洞号后新 track 点使用当时的 `actualHole`。
- [ ] 轨迹中的 `accuracy` 与当时页面显示的定位精度一致或可解释。

## 6. 结束并导出

- [ ] 完成需要测试的洞后点击“结束现场测试”；页面写入 `endTime`、已完成洞号和样本数量。
- [ ] 结束前确认没有仍在等待保存的 Tee/Green/确认操作。
- [ ] 点击“导出本场数据”（进行中为“导出现场数据”），下载 JSON 文件。文件名包含球场、Session 开始日期（UTC）和 Session ID 短标识；JSON 仍为 `schemaVersion: 1`。
- [ ] 导出文件顶层至少包含：`session`、`samples`、`confirmationEvents`、`metadata`；如启用轨迹，还应包含 `track`。
- [ ] 用项目 schema/validator 检查导出 JSON；检查失败时保留原文件和错误信息，不手改成“看起来正确”的数据。
- [ ] 在另一台电脑或下载目录打开文件，确认内容可读、数量与页面一致。
- [ ] 将真实 JSON 只保存在 `field-tests/private/` 或用户指定的私有位置；不提交 Git，不上传到公共仓库。
